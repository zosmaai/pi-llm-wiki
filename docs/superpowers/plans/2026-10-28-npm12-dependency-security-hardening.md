# npm 12 Dependency Security Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use /skill:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `npm audit` clean for every consumer of `@zosmaai/pi-llm-wiki`, gate that cleanliness in CI on both the repo graph and the consumer-resolved graph, and document both npm 12 install warnings (vulnerable transitives behind exact upstream pins, and default-deny lifecycle scripts) in one runnable user-facing page.

**Architecture:** Three layers, each guarded by a test so it cannot drift. (1) **Pinning:** the patched version set lives in `package.json#pnpm.overrides` for this repo's graph, and in one committed fixture `test/fixtures/consumer-audit/package.json` that models a consumer project; `test/package-structure.test.ts` asserts those two maps are deep-equal, and asserts every override key+version also appears in `docs/dependency-security.md`. (2) **Gating:** `.github/workflows/security.yml` switches its `audit` job from informational (`continue-on-error: true`) to a hard `pnpm audit --prod --audit-level=high`, and gains a `consumer-audit` job modeled on `packaged-mcp-consumer` in `ci.yml` that packs the tarball, installs it into the fixture project, prints the resolved versions, and fails on any high-or-worse `npm audit` finding. (3) **Documentation:** `docs/dependency-security.md` carries the exact override block, the clean-reinstall commands, the four gotchas, and the `npm install-scripts approve` path. No production code, no extension code, no QMD code changes.

**Tech Stack:** TypeScript (ES2022, ESM), Vitest 3 (tests, `test/**/*.test.ts`), Biome 2 (lint/format, `lineWidth: 100`), pnpm 9.15.4 (`packageManager`) for this repo, npm (10/11/12) for the consumer graph, GitHub Actions YAML, Starlight docs generated by `scripts/sync-docs.js`.

**Roadmap:** None. `docs/superpowers/roadmaps/2026-08-09-qmd-retrieval-roadmap.md` exists but covers QMD retrieval quality and is unrelated to this work.

**Phase:** Single-plan implementation.

**Originating issue:** [#321](https://github.com/zosmaai/pi-llm-wiki/issues/321) — "npm 12 installs: blocked native build scripts + vulnerable transitive dependencies".

## Context (read before starting)

A clean `npm install @zosmaai/pi-llm-wiki@0.12.5` in an empty project (npm 11.6.2; npm 12 audits identically) resolves **320 packages** and `npm audit` reports **9 vulnerabilities (1 moderate, 6 high, 2 critical)**. None of the vulnerable packages are ours:

| Package | Severity | Path | Patched in |
| --- | --- | --- | --- |
| `@modelcontextprotocol/server@2.0.0` | high, 4 advisories (GHSA-jm63-cq47-j5jp, GHSA-46jr-4wx8-v453, GHSA-rvq5-wwqv-78pq, GHSA-f897-62hf-6gxq) | `@tobilu/qmd` pins it exact at `2.0.0` | 2.3.0+ (latest 2.4.0) |
| `zod@4.2.1` | high (GHSA-mrhx-c7xc-m3w5) | `@tobilu/qmd` pins it exact at `4.2.1` | 4.6.6+ |
| `@simple-git/argv-parser@1.1.1` | critical (GHSA-v5rq-49vh-5v5c) | `@tobilu/qmd` → `node-llama-cpp@3.20.0` → `simple-git@3.36.0` | 2.0.1 |
| `simple-git@3.36.0` | critical (GHSA-x6jw-m9v5-85vh, GHSA-g4wm-2vf7-vfgr, GHSA-858h-whjf-mvg5) | same path | 4.0.1+ (nothing patched on 3.x) |
| `undici@8.10.2` | high, 7 advisories incl. TLS certificate validation bypass GHSA-2m5v-pch6-74hx | `@earendil-works/pi-coding-agent@1.4.0` pins it exact at `8.10.2` | 8.12.2+ (latest 8.12.3) |

Two structural facts drive the whole design:

1. **Upstream pins are exact.** `@tobilu/qmd` (we pin `2.8.3`, the latest release) pins its dependencies exactly, and so does `@earendil-works/pi-coding-agent@1.4.0` for `undici`. Our declared ranges (`^2.1.0` for `@modelcontextprotocol/server`, `^4.0` for `zod`) already resolve to clean copies at the top of our own graph; the vulnerable copies are *nested* under those exact pins.
2. **Only the root package's `overrides` are honoured.** npm ignores `overrides` declared by a non-root package, so we cannot fix the consumer graph from inside our published manifest. What we *can* do: fix our own graph with `pnpm.overrides`, ship a copy-pasteable `overrides` block, and prove with CI that a consumer who applies it ends up at `found 0 vulnerabilities`.

`undici@8.10.2` appears **only** in the consumer graph: `@earendil-works/pi-coding-agent` is a peer + dev dependency in this repo, so `pnpm audit --prod` here never sees it. That is why Task 4 adds a second, consumer-shaped audit job.

The repo's current override block (`package.json:106-115`) is actively harmful:

```json
  "pnpm": {
    "overrides": {
      "undici": "8.10.1"
    },
    "onlyBuiltDependencies": [
      "better-sqlite3",
      "node-llama-cpp",
      "sqlite-vec"
    ]
  },
```

`8.10.1` is inside the vulnerable range `8.0.0 - 8.12.1`.

**Verified target state** (reached `found 0 vulnerabilities` in a clean probe install, so the plan applies it verbatim rather than re-deriving it):

```json
{
  "undici": "8.12.3",
  "zod": "^4.6.7",
  "@modelcontextprotocol/server": "2.4.0",
  "simple-git": "4.0.2",
  "@simple-git/argv-parser": "2.0.1"
}
```

The **separate, non-security half** of #321: npm 12 flipped dependency lifecycle scripts to default-deny ([npm RFC 868](https://github.com/npm/rfcs/pull/868), npm/cli commit `5cd5150`), so `pi install npm:@zosmaai/pi-llm-wiki` warns that 6 packages have install scripts not covered by `allowScripts`: `node-llama-cpp@3.20.0` (postinstall builds the llama.cpp binary used for embeddings) and `tree-sitter-go@0.25.0`, `tree-sitter-python@0.25.0`, `tree-sitter-rust@0.24.0`, `tree-sitter-typescript@0.23.2`, `tree-sitter-javascript@0.23.1` (`node-gyp-build`). All six live inside the optional `@tobilu/qmd` subtree. Blocked scripts mean qmd has no embeddings and no tree-sitter chunking, so llm-wiki silently degrades to lexical-only recall. This half needs documentation only — the approval path is `npm install-scripts approve` naming those six packages, followed by `npm rebuild` (full command in Task 5 Step 3).

- [ ] **Step 2: Add the `consumer-audit` job**

Insert this job after the `audit` job and before the `trivy` job in `.github/workflows/security.yml`:

```yaml
  # The pi-pinned undici never appears in the graph above:
  # @earendil-works/pi-coding-agent is a peer + dev dependency here, so
  # `pnpm audit --prod` skips it. Consumers install without our lockfile and
  # resolve the newest versions our ranges allow (issue #128), and that graph is
  # the one that prints the audit block in issue #321. Same pack-and-install
  # shape as `packaged-mcp-consumer` in ci.yml, but audited instead of smoked.
  consumer-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      - uses: pnpm/action-setup@v6

      - uses: actions/setup-node@v7
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile
        env:
          PUPPETEER_SKIP_DOWNLOAD: true

      - name: Audit the consumer-resolved dependency graph
        shell: bash
        run: |
          set -euo pipefail
          consumer="$RUNNER_TEMP/consumer-audit"
          mkdir -p "$consumer"

          # prepack builds dist/, so no --ignore-scripts here.
          tarball=$(npm pack --pack-destination "$RUNNER_TEMP" --silent | tail -1)

          # The fixture carries the same overrides block docs/dependency-security.md
          # tells consumers to add; test/package-structure.test.ts keeps the two
          # maps equal, so this job audits the documented remediation.
          cp test/fixtures/consumer-audit/package.json "$consumer/package.json"

          cd "$consumer"
          # Lockfile is written on purpose: the audit must run against the exact
          # resolved graph. --ignore-scripts only skips native build steps, which
          # cannot change what `npm audit` reports.
          npm install --ignore-scripts "$RUNNER_TEMP/$tarball" "@earendil-works/pi-server"

          # Diagnostic only: npm ls exits non-zero on unresolved optional/peer
          # edges, so print the versions without letting them gate the job.
          npm ls simple-git @simple-git/argv-parser @modelcontextprotocol/server undici zod || true

          # Exits non-zero on any high-or-worse finding, which fails the job.
          npm audit --audit-level=high
```

Why `@earendil-works/pi-server` is installed explicitly: `@earendil-works/pi-coding-agent` imports it at runtime but does not declare it, so a lockfile-free consumer install can resolve nothing for it — the same reason `packaged-mcp-consumer` in `ci.yml:140-143` adds it. Why `npm pack` has no `--ignore-scripts`: `prepack` builds `dist/` (`package.json` `scripts.prepack`).

# Dependency Security

A clean install of `@zosmaai/pi-llm-wiki` on npm 12 can print two blocks that look
alarming and are not caused by this package: a vulnerability summary from
`npm audit`, and an `install-scripts` warning that native build steps were
skipped. This page explains what each one means and gives the commands that
resolve it. Issue #321 tracks both.

## The short version

- The audit findings come from the transitive tree of the optional
  `@tobilu/qmd` dependency, plus the `undici` pin inside the pi host. Pin patched
  versions in **your** `package.json` with an `overrides` block, then reinstall
  from scratch. The exact block is below, and this repository ships a working
  copy of such a project at `test/fixtures/consumer-audit/package.json`.
- The `install-scripts` warning is npm 12 defaulting dependency lifecycle
  scripts to deny. Approve the six packages it names, then `npm rebuild`.
- Do not run `npm audit fix --force`. It is not a fix here, and it will quietly
  downgrade this package.

## 1. Vulnerable transitive dependencies

A clean `npm install @zosmaai/pi-llm-wiki` resolves 320 packages and reports
9 vulnerabilities (1 moderate, 6 high, 2 critical):

| Package | Severity | Why it appears in your graph | Patched in |
| --- | --- | --- | --- |
| `@modelcontextprotocol/server@2.0.0` | high, 4 advisories | `@tobilu/qmd` pins it exact | 2.3.0+ |
| `zod@4.2.1` | high (GHSA-mrhx-c7xc-m3w5) | `@tobilu/qmd` pins it exact | 4.6.6+ |
| `@simple-git/argv-parser@1.1.1` | critical (GHSA-v5rq-49vh-5v5c) | `@tobilu/qmd` via `node-llama-cpp@3.20.0` via `simple-git@3.36.0` | 2.0.1 |
| `simple-git@3.36.0` | critical (GHSA-x6jw-m9v5-85vh, GHSA-g4wm-2vf7-vfgr, GHSA-858h-whjf-mvg5) | same path | 4.0.1+ |
| `undici@8.10.2` | high, 7 advisories, including TLS certificate validation bypass GHSA-2m5v-pch6-74hx | `@earendil-works/pi-coding-agent@1.4.0` pins it exact | 8.12.2+ |

Add this to your `package.json`. npm honours `overrides` only from the root
package, so we cannot apply it for you from inside our published manifest:

```json
{
  "name": "pi-llm-wiki-consumer-audit",
  "private": true,
  "overrides": {
    "undici": "8.12.3",
    "zod": "^4.6.7",
    "@modelcontextprotocol/server": "2.4.0",
    "simple-git": "4.0.2",
    "@simple-git/argv-parser": "2.0.1"
  }
}
```

`pi-llm-wiki-consumer-audit` is the fixture name used by this repository's CI;
keep your own `name` and paste the `overrides` block into your manifest.

Then reinstall from scratch and audit:

```bash
rm -rf node_modules package-lock.json
npm install
npm audit --audit-level=high
```

Expected result: `found 0 vulnerabilities`. This is the exact install the
`consumer-audit` job in `.github/workflows/security.yml` runs on every push and
pull request, so the block above is tested, not folklore. This repository
carries the same map as `pnpm.overrides`, which is what makes
`pnpm audit --prod --audit-level=high` clean here.

### Four things that will bite you

1. **Do not run `npm audit fix --force`.** Its chosen remedy is to downgrade
   `@zosmaai/pi-llm-wiki` to 0.12.2, which pulls the older `@tobilu/qmd` 2.5.3
   and loses the retrieval work since that release. It "resolves" the advisories
   by taking you to an unsupported version.
2. **Overrides only take effect on a clean reinstall.** An incremental
   `npm install` over an existing tree leaves a stale nested copy that npm marks
   `invalid: "2.4.0"`, and `npm audit` keeps reporting the old version. Delete
   `node_modules` and `package-lock.json` as shown above.
3. **`--omit=optional` does not silence the audit.** `npm audit` resolves from
   registry metadata, so `--omit=optional` removes `@tobilu/qmd` from
   `node_modules` while the advisories it brings still appear in the output.
   Use `overrides`, not `--omit`, to change what audit reports.
4. **`simple-git` 4.x replaces the `^3.36.0` that `node-llama-cpp` declares.**
   The override is a major-version jump through a dependency you did not choose.
   `node-llama-cpp` uses `simple-git` only to check model files out of a git
   repository, so the jump is expected to be safe, but it is **not
   runtime-tested**: nothing in this repository's CI downloads a model, so the
   `node-llama-cpp` checkout path against `simple-git` 4.0.2 is unverified.
   If a model download fails for you, that is the first suspect.

## 2. Blocked install scripts

npm 12 changed dependency lifecycle scripts to default-deny (npm RFC 868,
npm/cli commit `5cd5150`). A `pi install npm:@zosmaai/pi-llm-wiki` therefore
warns that 6 packages have install scripts not yet covered by `allowScripts`:

```text
node-llama-cpp@3.20.0        postinstall: node ./dist/cli/cli.js postinstall
tree-sitter-go@0.25.0        install: node-gyp-build
tree-sitter-python@0.25.0    install: node-gyp-build
tree-sitter-rust@0.24.0      install: node-gyp-build
tree-sitter-typescript@0.23.2 install: node-gyp-build
tree-sitter-javascript@0.23.1 install: node-gyp-build
```

All six are inside the optional `@tobilu/qmd` subtree, and all six are ordinary
native builds rather than fetched code, so this warning is a prompt to make a
deliberate choice rather than a signal of trouble.

Preview what is pending, then approve exactly those six and rebuild:

```bash
npm install-scripts ls
npm install-scripts approve node-llama-cpp tree-sitter-go tree-sitter-python tree-sitter-rust tree-sitter-typescript tree-sitter-javascript
npm rebuild
```

`npm install-scripts approve --all` is the blanket form. Prefer the named form so
a future dependency cannot inherit your approval by accident.

### What stays degraded if you leave the scripts blocked

`node-llama-cpp`'s postinstall builds the llama.cpp binary that produces
embeddings, and the tree-sitter grammars provide code-aware chunking. With the
scripts blocked, `@tobilu/qmd` installs but has no embeddings and no tree-sitter
chunking, so llm-wiki silently falls back to lexical-only recall: `wiki_reindex`
keeps its `lexical` component, `vectors` never gets content, and search quality
drops without any error to tell you. See [QMD Compatibility](qmd-compatibility.md)
for what the QMD index does and which parts need a model.

## Upstream constraints

The versions above are not lazily pinned by us. `@tobilu/qmd` declares its
dependencies at exact versions (`@modelcontextprotocol/server` 2.0.0, `zod`
4.2.1, `node-llama-cpp` 3.20.0), and `2.8.3` is the latest release, so a
consumer has nothing newer to move to inside qmd. `@earendil-works/pi-coding-agent`
1.4.0 pins `undici` exactly at `8.10.2`, which is vulnerable through `8.12.1`.
Until those upstream packages widen their ranges or move, an `overrides` block in
the consuming project is the only mechanism that reaches these advisories, which
is why it is documented here and asserted in CI rather than left to a lockfile
update.

## Real exposure, triaged

Not every advisory is equally reachable in the default configuration:

- The `@modelcontextprotocol/server` advisories are HTTP-transport specific
  (cross-client leakage, bearer-token handling). This package's MCP server runs
  as a local stdio process (`dist/mcp/index.js`), so those entries are not
  reachable in the default configuration.
- The `simple-git` and `@simple-git/argv-parser` advisories are command
  execution through unsafe git configuration, reachable only through
  `node-llama-cpp` checking out model files from an untrusted repository URL.
- `undici` is the operational one. The pi host uses it for outbound LLM traffic,
  so the TLS certificate validation bypass (GHSA-2m5v-pch6-74hx) and the cache
  poisoning entries affect real requests. If you only fix one, fix `undici`.
